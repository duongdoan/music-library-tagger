# App v2 MVP Implementation Plan

> Bản rút gọn theo yêu cầu "code luôn": mỗi task ghi file, giao diện và cách kiểm thử. Code nằm trong repo, không chép vào đây.

**Mục tiêu:** ứng dụng desktop gồm quét thư viện, bảng sửa kiểu Excel, sửa hàng loạt, thay đổi chờ, xem trước rồi ghi an toàn, lịch sử và hoàn tác.

**Kiến trúc:**
- Tauri 2. Lõi Rust trong `app/src-tauri` gồm `tags` (đọc/ghi theo định dạng, lấy từ spike), `db` (SQLite), `scan`, `stage`, `apply`, `history`.
- Giao diện React + TS + Vite trong `app/src`. Bảng dùng Glide Data Grid.
- Toàn bộ track nạp lên frontend (khoảng 55k dòng). Lọc và sắp xếp chạy ở frontend; thay đổi chờ lưu trong SQLite.

**Công nghệ:**
- Rust: tauri 2, lofty 0.25, id3 1.17, rusqlite (bundled), rayon, unicode-normalization, trash.
- Frontend: React 18, TypeScript, Vite, @glideapps/glide-data-grid 6.

**Spec:** `docs/business-rules/app/*.md`, `docs/features/app/*.md`, `docs/architecture/spike-report.md`.

## Ràng buộc chung
- Mọi phép ghi phải qua Xem trước (APP-WRITE-R1); sao lưu vào nhật ký trước khi ghi (R3); kiểm tra mtime và size ngay trước khi ghi (R4).
- Ghi theo từng định dạng (spike-report §1), không dùng API tổng quát của `lofty` để ghi.
- Định danh file bằng đường dẫn đầy đủ (APP-SCAN-R8).
- Chuẩn hoá NFC, cắt khoảng trắng đầu/cuối, gộp khoảng trắng liên tiếp (APP-TAG-R4).
- WAV: đọc ID3; ghi đồng bộ ID3 và RIFF INFO (APP-TAG-R10). WMA chỉ liệt kê (APP-TAG-R11).
- Kéo điền và dán chỉ tác động lên các dòng đang hiển thị (APP-STAGE-R17).

## Review Focus
1. File bị sửa bên ngoài sau lần quét: phải báo xung đột, không ghi (test trong `apply`).
2. Ghi lỗi giữa chừng: file gốc còn nguyên, có bản tạm `.mlt-tmp.*` thì phải dọn đi (test trong `apply`).
3. Tag lạ phải được giữ nguyên qua một vòng ghi rồi khôi phục (test trong `tags`).
4. App bị đóng đột ngột: thay đổi chờ vẫn còn khi mở lại, vì lưu trong DB (test trong `stage`).
5. Hoàn tác sau khi file đã bị sửa tiếp: trường đó phải bị đánh dấu và mặc định bỏ chọn (test trong `history`).

## Tasks
1. **Scaffold:** Tauri + React + Vite trong `app/`, build được. Kiểm thử: `npm run tauri build -- --debug` hoặc `cargo check`.
2. **`tags`:** module đọc/ghi gồm `read_track(path) -> TrackTags` và `write_track(path, &Changes)`, cùng `dsf.rs`, `riff.rs`, `flac_fast`. Kiểm thử: dữ liệu âm thanh không đổi, khôi phục xong tag giống hệt (dùng file mẫu tự tạo trong test).
3. **`db`:** schema gồm `sources`, `tracks`, `staged`, `runs`, `journal`; các hàm CRUD. Kiểm thử bằng DB trong bộ nhớ.
4. **`scan`:** duyệt song song, quét tăng dần theo mtime/size, chạy tiếp được, huỷ được, phát sự kiện tiến độ. Kiểm thử trên thư mục tạm.
5. **`stage` + `apply` + `history`:** thay đổi chờ; lượt ghi có nhật ký, phát hiện xung đột, ghi qua bản tạm, xác minh lại; hoàn tác thành thay đổi chờ đảo ngược. Kiểm thử tích hợp trên thư mục tạm.
6. **Lệnh Tauri:** `add_source`, `list_sources`, `scan_source`, `cancel_scan`, `load_tracks`, `stage_set`, `stage_list`, `stage_discard`, `apply_run`, `cancel_apply`, `list_runs`, `undo_run`.
7. **Giao diện chính:** sidebar (nguồn, cây thư mục, bộ lọc nhanh, lịch sử), bảng Glide (sửa ô, chọn vùng, kéo điền theo `onFillPattern`, dán, Cmd+Enter, Delete), inspector (một file / nhiều file), thanh hành động.
8. **Hộp thoại:** Tìm & thay (regex, mẫu đã lưu), Tag từ tên file, Đánh số track, Xem trước & áp dụng, Báo cáo, Lịch sử.
9. **Kiểm thử end-to-end** trên bản sao file mẫu, chạy app thật.
